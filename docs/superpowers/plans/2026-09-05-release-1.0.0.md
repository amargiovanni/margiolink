# MargioLink 1.0.0 security and performance implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development to implement and review each task, then run the release gates.

**Goal:** Fix all seven confirmed review findings, add regression tests, and publish version 1.0.0 through GitHub and the existing Cloudflare Worker.

**Architecture:** Keep Hono, D1 and the existing public/API contracts. Reuse the current middleware and UI patterns. Bind password grants to the link and current credentials, bound request bodies before parsing, paginate within D1 limits, and reduce unnecessary analytics work through demand loading and private caching after authentication.

**Tech Stack:** Node 24, TypeScript, Hono, Cloudflare Workers/D1, React, TanStack Query, Vitest and Playwright.

**Spec:** The user explicitly authorized all fixes, effective tests, commit, push, publication, tag and release 1.0.0. The concrete findings, resolutions, and validation scope are recorded in [`docs/reviews/2026-09-05-security-performance.md`](../../reviews/2026-09-05-security-performance.md).

## Task 1: Public endpoint security and single authentication guard

Files: `src/routes/redirect.ts`, `src/auth/link-token.ts`, API router/auth middleware files, a small body-limit middleware if needed, and corresponding Worker tests.

- [ ] Add regression tests: POST on inactive/expired protected links must match GET lifecycle policy, including expired fallback; soft deletion stays 404; no grant cookie is minted for denied links.
- [ ] Add tests: changing password invalidates previous grants; renaming a link and reusing its slug with a new protected link does not authorize the new destination; unchanged credentials still accept a grant and expiry remains ten minutes. Reject legacy slug-only grants on deployment.
- [ ] Share the lifecycle checks between GET and POST, before password derivation. Bind token signatures to immutable link ID, slug and current password credentials/version, using unambiguous encoding and constant-time verification. Do not expose password digests in the cookie.
- [ ] Enforce a 16 KiB body limit before buffering/parsing on public login and password submission. The limit must also count streamed bodies without Content-Length and dishonest length headers. JSON errors use 413 with an error code; public form errors are safe and readable. Preserve normal requests. Test large ignored JSON fields, form bodies, stream boundary handling and that excessive bodies do not cause password derivation or D1 writes.
- [ ] Register `requireSession` exactly once for every private API route. Keep login public. Update route coverage tests and count real session SELECTs in an authenticated stats/meta request: exactly one.
- [ ] Run covering tests, typecheck and lint on amended files. Commit and report.

## Task 2: D1-safe pagination and search

Files: `src/db/tags.ts`, `src/routes/api/links.ts`, `web/src/lib/queries.ts`, `web/src/pages/Links.tsx`, corresponding Worker/React tests and one focused browser regression if useful.

- [ ] Demonstrate the API failure with 120 links and a long search; demonstrate UI pagination failure beyond 200 records.
- [ ] Keep existing API support for limit up to 200, but batch tag hydration in chunks of at most 100 bound parameters.
- [ ] Validate search by UTF-8 bytes: at most 48 bytes because SQL adds two percent signs and D1 allows 50 bytes per LIKE pattern. Reject invalid queries with 400, and show useful feedback in the UI. Cover ASCII and multibyte exact boundaries, not only JS string length.
- [ ] Replace growing-limit requests with fixed 20-item pages and offset/cursor progression, accumulating results without duplicates. Load more must reach records beyond 200, keep previous rows during loading/errors, retry the failed page, reset cleanly when search/status/tag filters change, and continue to work after create/update/delete/restore invalidation.
- [ ] Cover API >100 hydration, UI >200 pagination and filter reset, error/retry and long-search feedback. Commit and report.

## Task 3: Bounded analytics loading and authenticated caching

Files: stats route and related new helper if needed, query hooks, LinkDetail/Overview and small demand-loading components/hooks, corresponding Worker/React tests.

- [ ] Replace eager loading of every detailed breakdown with viewport/demand loading while keeping charts discoverable, accessible and usable with keyboard and a fallback if IntersectionObserver is absent. No loss of analytics dimensions. Avoid optional panel requests until needed; keep summary/timeseries immediately available.
- [ ] Add an explicit 60-second stale window for non-live statistics in TanStack Query; live feed keeps its 10-second polling and pause behavior.
- [ ] Cache successful aggregate stats responses for closed periods for at most 60 seconds using the Workers Cache API after session validation. Cache identity includes request URL, release version, retention configuration and authenticated session identity; never serve cached data to an expired/revoked session or cache failures. Outgoing responses must be private/no-store; cache storage headers stay internal. Live feed is never cached. Test miss/hit, separate ranges/links/sessions, revoked sessions, invalid inputs, cache errors falling back to live D1, and TTL. Avoid caching open/future ranges.
- [ ] Preserve existing raw-based semantics, including sensitive dimensions: do not replace them with suppressed aggregates. Test that original count outputs are unchanged and cold initial detail loading performs fewer raw scans; repeated closed-period requests use cached payloads but still authenticate once.
- [ ] Run meaningful focused tests and inspect an actual browser build for lazy-loading behavior. Commit and report.
